### Ⅲ. 游戏流程

> 游戏背景：
> 玩家需要扮演一名穿越到地牢世界的大学生，在地牢中生存下来，积极探索地图，获取道具以提高分数，努力达成获胜条件，实现穿越回现实世界的终极目标
> 在地牢冒险中，大学生勇者会遇到许多与他穿越前相似的道具，这需要他自己去辨别功能，然后更好地利用道具达成终极目标

1. 首先输入角色名字，点击开始游戏选项，等待游戏初始化后开始游戏
2. 每局游戏中，角色会获取固定数值的初始状态，具体如下:
   1. 健康度: 100
   2. 耐力值: 200
   3. 武力值: 10
   4. 得分: 0
3. 所有地牢房间在初始化后对玩家来说是不可见的，该状态下玩家无法获取房间中怪物和物品信息。只有当玩家进入一个房间后，该房间才会标记为对玩家可见，并且房间中怪物和物品的信息可以被玩家随时查询，以帮助玩家完成探索决策

### Ⅳ. 游戏机制

**0. 数值计算底层机制：**
   所有涉及到需要变动角色状态值的操作，均按照以下公式处理
   $$ 玩家状态值 += (int)(改变量 + 0.5)$$
   或
   $$ 玩家状态值 -= (int)(改变量 + 0.5)$$

**1. 耐力值消耗**
   角色每进行一次移动需要耗费基础值10点耐力值，额外的耐力值消耗取决于角色背包中物品的总质量，额外消耗的耐力值与总质量成正比。计算方法如下:
    $$ 每次移动消耗耐力值 = 10 + 背包中物品总质量 * 2$$
    
**2. 物品价值**
   每件`物品/武器`的价值分为$[1, 10]$十个层次，分别对应$[1.1, 2.0]$十个档次的额外加成系数。当角色获取道具时触发的道具效果加成与该物品对应的额外加成系数相关联，计算方法如下:
    $$ 实际效果加成 = 本身效果加成 * (0.1 * 物品价值 + 1.0)$$

**3. 胜负条件判定**
   玩家每次移动后，都会根据相应的状态进行一次游戏胜负的条件判断，若满足其中条件则进行胜负判断并结束游戏，否则继续该局游戏
   - **胜利条件**
       1. 角色存活，计算此时得分数
       2. 角色存活，得分达到预期阈值
   - **失败条件**
       1. 在探索完所有地牢房间前，角色健康度降至0

**4. 怪物房间**
   玩家每次进入房间后，若房间内有怪物，则会强制玩家进入战斗环节。每次进入战斗模式均会将`该房间标记为可见`。该环节有`讨伐`和`逃跑`两种选项:
   1. **讨伐 fight()**
      1. **怪物状态判断**
         1. **怪物健康度 > 75%**
           该状态下，`怪物疲惫状态置为0`
         2. **怪物健康度 <= 75%**
           该状态下，`怪物疲惫状态置为1`
        > 角色每次与怪物房间交互后，若`怪物疲惫状态为1`，则角色在耐力值消耗阶段的`最终消耗耐力值*0.8`
      2. **玩家与怪物交互**
         1. **`玩家武力值大于怪物武力值`:**
            该房间内的`怪物被打败`，`怪物健康度降至0`，该房间中的怪物被清除掉，同一局内该房间不会再生成怪物；
            玩家健康度不变；
            玩家可获取`1.0倍的怪物对应积分`；
            玩家`进入怪物所在房间`；
            `正常消耗耐力值`
         2. **`玩家武力值等于怪物武力值`(优先判定):**
            该房间内的`怪物被打败`且同一局内不会再生成；
            `玩家健康度-=怪物武力值*0.1`；
            触发`斩杀`效果，玩家可获得`1.5倍怪物积分`；
            玩家`进入怪物所在房间`；
            `正常消耗耐力值`
         3. **`玩家武力值小于怪物武力值`:**
            怪物不会被打败该房间内`怪物健康度-=玩家武力值*0.6`；
            `玩家健康度-=怪物武力值*0.4`，玩家`不会获取怪物积分`；
            同时玩家不会进入怪物所在房间，仍`停留在进入怪物房间前的房间内`；
            `耐力值消耗为最终消耗值*0.6`
   2. **逃跑 run()**
        无论怪物和玩家武力值大小与否，怪物健康度不改变；
        `玩家健康度-=怪物武力值*0.4+怪物健康度*0.1`；
        *有道是：“留得青山在，不怕没柴烧。”* 玩家耐力值会进行一定幅度减少，`耐力值消耗为正常情况下最终耐力值消耗*0.4`；
        同时玩家会停留在进入怪物房间前的房间内

**5. 角色状态值**
   道具的增益/减益效果生效后，健康度区间始终为$[0, 100]$，耐力值区间始终为$[0, 200]$，二者数值始终不会超过设定阈值

**6. 道具获取**
    角色每到一个房间后，若为非怪物房间，则会强制将房间中存在的道具加入背包并即时生效；若为怪物房间，则需角色先完成战斗环节，若结果为角色可以进入该怪物房间，则再将房间内所有道具加入背包

**7. 初始化**
    每次开始一局游戏时，将所有道具和怪物随机分配到不同房间中，每个房间最多同时拥有2个道具和1个怪物
> 所有房间、道具(包括Food, Scholarism, Weapon三个分支类)、角色类型的对象初始实例化过程均放在ZorkUL::init()中，以便统一修改

### Ⅴ. 代码层面执行序

**1. 游戏初始化环节**
   每次开始一局游戏时，首先对游戏中地图进行加载，将道具和怪物房间进行初始化，同时在某一位置进行角色位置初始化

**2. 人机交互环节**
   1. **角色移动阶段**
        将角色将要移动到的房间存入`*nextRoom`中，判断`*nextRoom`是否指向`NULL`，即下一方向是否有房间，若没有则打印撞墙信息并直接结束交互环节
   2. **怪物房间判定阶段**
        输入的房间指针为`*nextRoom`，对其进行判断并将其中的Monster对象与Character对象进行交互
        - `monsterRoomCheck`: 
            0 -> 普通房间
            1 -> 怪物房间
      1. 怪物房间(两个选项)
         1. 讨伐
            > 会先根据怪物健康度改变怪物疲惫状态标志位`tiredness`
            1. 玩家武力值大于怪物武力值
                `moveCheck` = 1; 
                `staminaCheck` = 0;
            2. 玩家武力值等于怪物武力值
                `moveCheck` = 1;
                `staminaCheck` = 0;
            3. 玩家武力值小于怪物武力值
                `moveCheck` = 0;
                `staminaCheck` = 1;
         2. 逃跑
            `moveCheck` = 0;
            `staminaCheck` = 2;
      2. 非怪物房间 
            `moveCheck` = 1;
            `staminaCheck` = 0;
    
   3. **总判定环节 Judge**
        每到该环节时，新创建一个`Judge*`类型的变量`*judge`，并将角色指针类型`Character*`、角色下一步将要到达的房间指针`*nextRoom`和当前房间的指针变量`*currentRoom`作为参数传入，进行各种状态量的修改和判定。当该环节执行完毕后，随时将该`Judge*`类型对象指针销毁并释放空间
      1. **耐力值消耗阶段**
           - 依据`Character`内的`staminaCheck`进行判定: 
               0 -> 正常消耗: 1.0倍消耗
               1 -> 讨伐情况三: 0.6倍消耗
               2 -> 逃跑: 0.4倍消耗
      2. **角色位置判断阶段**
           - 依据`Character`内的`moveCheck`进行判定:
               0 -> 角色不进行移动
               1 -> 角色进行移动
      3. **获取道具阶段**
           若角色当前所在房间存在道具，则将其全部加入背包并即时生效
      4. **玩家状态值判定阶段**
           1. 若玩家健康度为0，则将`winOrLost`置为0，并直接跳到下一阶段
           2. 若玩家耐力值为0，则将`winOrLost`置为1
           3. 若玩家分数达到设定阈值，则将`winOrLost`置为2，并跳到下一阶段
      5. **胜负条件判定阶段**
           - 依据`ZorkUL`中的`winOrLost`进行判定:
               0 -> 游戏失败并结算分数
               1 -> 游戏胜利并结算分数
               2 -> 完美胜利并结算分数

**3. 本局游戏结束**

### Ⅵ. 问题总结

1. 已解决的问题
   1. 自定义两个类之间互相引用，并在初始化时在A类中实例化B类，出现无法进行实例化的编译错误
   2. 在头文件中声明了私有指针变量的前提下，在其代码实现时又对同名同类型变量进行new实例化，导致后续使用该变量时无法准确定位该指针变量实际指向的地址，出现段错误(指针乱指)
   3. 在弹窗中处理传入的指针类型变量，并根据点击的按钮不同实现不同功能
   
2. 尚未解决的问题
   1. 关于允许移动状态位的更新/判定可能存在bug，只在某些特殊情况下会出现进入房间交互异常的情况
   2. 胜负判断条件中的完美胜利条件判定存在bug，未在预期步骤完成判定
   3. 代码结构过于冗杂，功能模块化并未贯彻
