# TicketingSystem - 票务交易系统

> **“让每一次购票都精准无误，让每一张票都物归其主。”**

<!--[Language: C++ / Java / Python]-->
<!--[Status: Active]-->

本项目是一个模拟真实场景的**高性能票务交易系统**。旨在解决大规模用户并发访问下的**超卖（Overselling）**与**数据一致性**问题。系统实现了从用户查询、下单购买到库存扣减的完整业务闭环，是学习高并发处理与分布式事务的绝佳范例。

---

## 项目概述

在互联网抢票场景（如演唱会、火车票）中，核心挑战在于如何在高并发下保证库存的准确性和交易的公平性。本项目通过**缓存穿透防护**、**数据库事务控制**及**乐观锁/悲观锁机制**，模拟了亿级流量下的票务处理逻辑。

### 核心亮点
- **防超卖机制**：利用数据库行锁或 Redis 分布式锁，确保库存扣减的原子性。
- **高性能缓存**：引入 Redis 缓存热点数据，降低数据库压力，QPS 提升显著。
- **事务回滚**：保证“扣库存”与“生订单”操作的 ACID 特性。

---

## 核心功能

### 1. 业务功能模块
- **用户端**：支持用户登录、余票查询、下单购买、订单查询。
- **管理端**：支持场次管理、票价设置、库存初始化、销售统计。

### 2. 数据持久化
- **MySQL**：存储用户信息、订单详情及最终票务库存（强一致性）。
- **Redis**：缓存热门场次的票数，用于快速预扣减和库存展示。

### 3. 异常处理
- **熔断降级**：当系统负载过高时，自动拒绝非核心请求。
- **幂等性设计**：防止用户重复点击导致的重复下单。
